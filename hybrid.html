Doxket hybrid forensics: blueprint

The full flow of the planned hybrid: the main project's breadth and scoring, with the prototype's measuring investigator in the middle. Every diagram is colour-coded by where the part comes from, so you can see what already exists, what to port, and what to write new.

1 · When each part starts

Two streams run at once: the forensics service analyses pixels and files while Django's early review reads the content. The agent waits for both, because it needs every lead.

sequenceDiagram
  autonumber
  participant U as User / claim
  participant D as Django
  participant G as Forensics service
  participant R as Review (Celery)
  participant A as Agent
  participant S as Network + scoring
  U->>D: Upload file
  D->>D: Save original, preview page 1, fingerprint file
  D->>G: POST /analyze, answered 202 at once
  G->>G: Triage, upright pages, document or photo
  G-->>D: Rotations known
  D->>R: Start EARLY review
  par Forensics service
    G->>G: PDF structure, classical filters, OCR layout, pixel forensics, capture mode
    G-->>D: Track results, page by page
  and Early review
    R->>R: Transcribe, content check, AI check, seals, Tesseract words, word measurements
    R->>R: Revisions, PDF edits, DOCX checks
  end
  D->>R: All required tracks landed, start FINAL review
  R->>R: Cross-page check, digit recheck, text strips + consistency, laid-over text, expert checks
  R->>A: All leads + candidates + page images
  loop Up to 24 steps
    A->>A: Tool call, read result, decide next
  end
  A->>R: submit_report
  R->>R: Grounding, one retry back to agent if a finding fails
  R->>S: All signals
  S->>S: Network check, region merge, score, band
  S->>R: Score ready, LLM writes narrative
  R->>D: Release, or hold for human review
  D-->>U: Result in UI and claim
  • Watchdogs (exist): a running scan silent for 15 minutes is closed with what landed; a scan queued for 60 minutes fails.
  • Early vs final review (exists): early runs without OCR or tracks; final re-grounds every quote and adds the parts that need tracks.

The 14 content finding types

Template marker, impossible date, arithmetic mismatch, amount in words mismatch, cross-page contradiction, issuer vs signatory mismatch, implausible content, language anomaly, vague boilerplate, unsigned signature field, locale mismatch, form overprint, concealment, incomplete GST invoice.

The 13 tools

ToolFromWhat it returns
view_pageprototypeThe whole page as an image
zoomprototypeA close crop of a box, plus the word ids inside it
read_textprototypeMore lines with word ids; should also offer the transcription
find_peersprototypeFair peers for a word: same line, same colour and size, same number format
measureprototypeThe 7 measurements for chosen words
compareprototypeTarget vs peers per feature; "stands out" only past a threshold and 3× the peers' spread
digit_widthsprototypeEvery formatted number with its width; OUTLIER when peers agree better with each other
glyph_checknewWraps OCR-layout results for a box: letters drawn differently, pixel-identical letters (copied text), line geometry
region_forensicsprototype + newCompression and grain vs the page, copy-move hits, and pixel-forensics boxes touching the region
revision_diffnewWhat changed in a page or box between PDF saves ("from → to")
pdf_objectsnewFor a box: whiteout under text, second font copy, covers, redactions
compare_marksnewCompares two stamps or seals: score and verdict
validateprototypeAadhaar, PAN, GSTIN and date checks on any text
submit_reportprototypeEnds the loop; goes through grounding

Grounding rules (code)

  • Text findings (style, ink, digits, glyphs): the exact words were measured with measure, compare, digit_widths or glyph_check.
  • Region findings (compression, grain, copy-move, patch): region_forensics ran on an overlapping box.
  • File findings: revision_diff or pdf_objects ran, or a matching file lead exists.
  • Visual-only findings: allowed, but scored as a weak signal.
  • Fails: the agent is told once and may measure and resubmit; if it still fails, the finding is kept as info, not scored.

7 · Scoring (code)

Main's scorer, with one important change: an agent finding's weight comes from its evidence type (for example "digit-width outlier confirmed by compare"), never from the severity the LLM chose. The weights are then fitted on labelled data.

  classDef new fill:#fdebc8,stroke:#ba7517,color:#1d211f
  S1["Content signals"] --> MAP
  S2["Agent findings<br/>by evidence type"] --> MAP
  S3["File signals<br/>revisions, PDF edits, structure"] --> MAP
  S4["Pixel + metadata signals"] --> MAP
  S5["Network signals"] --> MAP
  S6["Expert check results"] --> MAP
  S7["AI-image signal"] --> MAP
  MAP["Signal table<br/>tell, soft, pass, info, warning<br/>likelihood ratio per type"] --> RM
  RM["Merge by region<br/>same spot on a page = one region"] --> IV{"Holds a value, and two<br/>measured families agree?"}
  IV -->|yes| TL["Tell: Inserted value"] --> DC
  IV -->|no| DC
  DC["Diminishing credit<br/>strongest in full, others at 0.25<br/>top region full, next two at 0.25"] --> CORE
  CORE["Start at 5% prior, add evidence<br/>p = higher of sigmoid and tell floor"] --> BD{"Band"}
  BD -->|"p 0.70+ or any tell"| HI["High: highly risky"]
  BD -->|"p 0.30+ or a warning"| MD["Medium: suspicious"]

Measured families for the "Inserted value" rule: geometry, lettering, pixel, ink. In the hybrid, agent evidence counts as a measured family when it came from compare, digit_widths, glyph_check or region_forensics.

10 · Build order

Each step can be tested on its own before the next one starts.

  1. Word measurements in Django. Port word features and digit-width peers into the review as code-only checks. Test: numbers match the prototype on the same pages.
  2. Merge the style checks. One consistency check from the prototype's line/group logic and main's text strips. Test on the labelled set.
  3. Lead list. Collect every candidate from evidence and content into one list with boxes and numbers.
  4. Agent workspace and tools. Port the 10 prototype tools onto Django's page data; add glyph_check, revision_diff, pdf_objects, compare_marks.
  5. Agent loop and LLM client. Port the loop with Gemini and Claude support, limits and usage tracking.
  6. Grounding with one retry.
  7. Signal mapping. Map each evidence type to a signal; agent evidence joins the "Inserted value" families.
  8. Switch and shadow run. Run the agent next to the render check behind a setting; compare both on the eval harness.
  9. Eval and calibration. Fix the harness to read the new score and skip the cache; fit the likelihood ratios.
  10. Extras. DOCX support, grounding against OCR, human review updating the score, cost tracking for the agent and Sightengine.
